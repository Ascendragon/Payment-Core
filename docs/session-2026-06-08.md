## Глава 1. Починка PHPStan-гейта (шаг 0.3)

**Запрос:** «Пойдём пошагово, главная цель — стать экспертнее, а не нахуярить код.»
Начали с самого маленького шага 0.3.

### Что нашли (проверкой по артефакту, не по ROADMAP)
В корне оказалось **четыре** phpstan-файла, и каждый «рабочий» был сломан по-своему:

| Файл | Level | baseline | в гите | реальность |
|---|---|---|---|---|
| `phpstan.neon` | 8 | нет | gitignored | локальный, перекрывал всё → 50 ошибок |
| `phpstan.neon.dist` | 5 | нет | да | **именно он побеждал в CI** → 19 ошибок |
| `phpstan.dist.neon` | 6 | да | да | **не парсился** (`includes` внутри `parameters`) |
| `phpstan-baseline.neon` | — | — | да | залочен под level 8 |

**Механизм бага №1 — приоритет автопоиска.** PHPStan без `-c` берёт первый из
`phpstan.neon` → `phpstan.neon.dist` → `phpstan.dist.neon`. «Хороший» конфиг лежал
в самом низком слоте, его перехватывал голый `phpstan.neon.dist`.

**Механизм бага №2 — `includes` под `parameters`.** `includes:` — секция верхнего
уровня, брат `parameters:`, а не ребёнок. Из-за вложенности конфиг крашился и
baseline **никогда не подключался**.

**Механизм бага №3 — baseline залочен под level 8.** На level 6 восемь его
паттернов (`numeric-string`, `offsetAccess` — это проверки level 7+) не матчились
→ `ignore.unmatched (non-ignorable)` → 8 фантомных ошибок. По умолчанию
`reportUnmatchedIgnoredErrors: true`.

### Реальные цифры (прогнали вживую)
- `phpstan.neon.dist` (L5, в CI): **19 ошибок**
- `phpstan.dist.neon` (L6+baseline): **Invalid configuration** (краш)
- `phpstan.neon` (L8): **50 ошибок**
- L6 + исправленный `includes` + baseline: **8** (фантомные unmatched)
- L8 + baseline: **1** (Symfony-тип `ParamConfigurator` в авто-генерируемом
  `config/reference.php`)
- L8 + baseline + `excludePaths: config/reference.php`: **`[OK] No errors`** ✅

### Решение (выбор пользователя): **Level 8**
Почему L8, а не L6: baseline уже под него заточен (остаётся починить 1 ошибку,
а не перегенерировать), строже всего, и держит `numeric-string`-дисциплину —
которая прямо ловит наш `Money`-косяк (C1/C2).

### Что сделали
- Удалили `phpstan.neon.dist` (голый L5) и локальный `phpstan.neon`.
- Оставили `phpstan.dist.neon` как единственный конфиг: level 8, `includes` наверх,
  `excludePaths: config/reference.php`.
- Приёмка: `vendor/bin/phpstan analyse` без `-c` → `[OK] No errors`.
- Коммит `d1e02ac` (заскоупленный — без `ci.yml`/`ROADMAP.md`).

### Уроки
- **Baseline = бэклог рефакторинга, а не мусорка.** Записи `bccomp ... expects
  numeric-string, string given` в `Money.php` — это и есть C1/C2; починим деньги в
  Фазе 1 — исчезнут сами.
- **«Голый level 5» опаснее отсутствия анализа** — даёт ложное чувство защищённости.
- **Имя файла = безопасность приоритета.** Канон лучше держать в слоте, который
  труднее перекрыть (обсудили трейд-офф `phpstan.neon.dist` vs `phpstan.dist.neon`).

## Глава 2. Переписывание CI (шаг 0.5)

**Запрос:** «Как назвать коммит и погнали дальше.»

### Диагноз старого `.github/workflows/ci.yml` (построчно)
1. health-check Postgres битый: незакрытая кавычка + нет `--health-interval/-timeout/-retries`.
2. **Нет `steps:` вообще** — джоба поднимала сервис и ничего не делала. Два коммита
   `fix` правили только отступы.
3. Имя БД не совпадало: сервис `payment_core_test` vs `.env`-DSN `app`.

### Факты, собранные под пайплайн (всё по артефакту)
- PHP `>=8.4`; расширения: bcmath, ctype, iconv, redis, **http** (пекл!), + intl/mbstring/pdo_pgsql для CI.
- БД PostgreSQL 16; `.env.test` не переопределяет `DATABASE_URL` → хост `postgres`
  (docker-имя, в CI не резолвится) → задать `DATABASE_URL` в CI явно.
- Схемы: DAMA нет → CI сам прогоняет миграции.
- **Сервисы нужны только Postgres** — доказано: `transfer()` не дёргает Redis-метрики
  (не инжектятся в `TransferService`) и брокер (outbox; шина не коннектится при
  конструировании).
- ⚠️ **phpstan-symfony требует скомпилированный контейнер** (`var/cache/dev/...Container.xml`)
  → в CI перед phpstan нужен `cache:warmup`. Неочевидный затык.
- phpunit строгий: `failOnDeprecation/Notice/Warning = true`.

### Запах зависимости: `ext-http` (стал шагом 0.7)
- `composer why ext-http` → «никто не зависит»; 0 использований в `src/`.
- Это pecl_http — болезненная сборка в CI, и она блокировала бы `composer install`.
- **Senior-ход:** усомниться в зависимости, а не тащить боль в окружение. Удалили
  строку из `composer.json`.
- **Урок:** трогаешь `require` → `composer.lock` пересобирается и коммитится в том
  же изменении (поймали рассинхрон через `composer validate`; починили
  `composer update --lock`, версии пакетов не поехали — diff 2/3 строки).

### Каркас пайплайна (порядок = fail-fast, дешёвое раньше дорогого)
`checkout → setup-php 8.4 → composer cache+install (--no-scripts) → cache:warmup →
php-cs-fixer --dry-run → phpstan (L8) → migrate → phpunit`.

Неочевидные решения: `--no-scripts` (чтоб не дёргать assets/importmap — флак),
отдельный `cache:warmup` (контейнер для phpstan), `DATABASE_URL` как job-level env
(перебивает `.env` в любом окружении).

### Pre-flight (проверили локально, до пуша)
- YAML валиден (9 шагов распарсились).
- `composer validate` → нашли рассинхрон lock → починили.
- `php-cs-fixer --dry-run` → зелёный (`files: []`).
- phpstan → зелёный.
- **Осталось:** запушить ветку `dev` → подтвердить зелёный ран (единственная честная
  проверка CI — на самом GitHub).

### План коммитов (атомарно, на `dev`)
`build(deps): drop unused ext-http` → `ci: add working pipeline` → `style(phpstan): tidy`.
**Урок про scope:** не сметать в коммит несвязанное (`ROADMAP.md` и пр.) — без `git add -A`.

## Глава 3. Полный обзор + дорожная карта

**Запрос:** «Сделай полный обзор и пошаговую карту с упором на рост до Senior+,
качественную архитектуру, теорию, трейд-оффы.»

### Центральная находка: механизм регрессии схемы (N1) — доказан по миграциям

| | Миграция 1 (рукописная, *хорошая*) | Миграция 2 (`make:migration` из сущностей) |
|---|---|---|
| balance | `numeric(18,2) CHECK (balance>=0)` | `VARCHAR(255)` — CHECK исчез |
| payment | `id UUID`, `amount numeric CHECK>0`, FK | `id INT`, `amount VARCHAR(25)`, без FK |
| идемпотентность | `UNIQUE (account_id, key)` | `UNIQUE (key)` — глобальный |
| audit | JSONB + индексы | JSON, индексы дропнуты |

`down()` миграции 2 **восстанавливает хорошую схему** → это чистая деградация.
Причина: `make:migration` сравнил БД с **анемичными** сущностями (`Account.id` —
`?string` с `getId(): ?int`, `balance` — `#[ORM\Column(length: 255)]`) и верно
снёс всё, что ORM «не видит».

> **Урок senior-уровня:** ORM-маппинг — это **авторитет над схемой**. Анемичные
> сущности → инструмент молча удаляет CHECK / NUMERIC / FK / составной UNIQUE.
> В финтехе схему поэтому часто **забирают** у ORM в рукописные миграции.

### Остальные находки (подтверждены кодом)
- **C1** баланс `VARCHAR`; **C2** публичный конструктор `Money` минует `of()`;
  **C3** `acquire()` вне транзакции → «отравленный ключ» в `Processing`.
- **NEW-1** перевод на 0 проходит; **NEW-2** мёртвый `messageBroker` в DI;
  **NEW-4** ключ стал глобальным; **NEW-5** `FOR UPDATE` в autocommit — no-op;
  **NEW-7** получатель апдейтится мимо `Money` (CAST).
- **Новое в этой сессии:** **NEW-9** сервис кидает голый `\InvalidArgumentException`
  на несовпадение валюты, хотя есть `CurrencyMismatchException`; **NEW-10** у
  `Money` нет `add()` + разнобой `Uuid`-объект vs строка на границе DBAL;
  **Q6** `composer audit` — 36 advisories / 14 пакетов.

### Что сделали
- Перечитали ядро (`TransferService`, `Money`, `DbalIdempotencyStore`, обе миграции,
  `Account`) — каждое утверждение карты подтвердили артефактом.
- Обновили [ROADMAP.md](../ROADMAP.md) до ревизии **2026-06-08**: сетка «поднята»,
  §1.4 переписан с доказанным N1, новые находки, статусы Фазы 0, навигация.
- Синхронизировали авто-память (прогресс + ключевой урок N1).

## Глава 5. Шаг 1.0 — кто владеет схемой (решение + план)

### Разобрали как сеньор — пятью диагностическими вопросами
- **Q1** Может ли кандидат-хозяин выразить инварианты? Doctrine **не умеет CHECK** →
  ORM в принципе не полный хозяин для денег.
- **Q2** Кто использует сущности в рантайме? На write-пути — **никто** (DBAL) →
  у мёртвых сущностей вся власть и ноль ответственности.
- **Q3** Цена ошибки и обратимость? Финтех: высокая/низкая → максимум явного
  контроля над DDL → миграции.
- **Q4** От какого сбоя защищаемся? От того, что видели: `make:migration` молча
  деградировал схему → вариант B убирает footgun.
- **Q5** Что теряем? Удобство генерации. Но схема маленькая → дёшево. (В большом
  CRUD с простыми ограничениями выиграл бы вариант A — **контекст решает**.)

Добивающий аргумент: код **уже на 80% в B** (raw DBAL, мёртвые сущности) → B =
узаконить существующее; A = разворачивать write-путь обратно в ORM.

> Честная смена позиции: в прошлой карте склонялись к A «ради обучения». С новыми
> фактами (доказанная регрессия + полностью DBAL write-путь) рекомендация изменена
> на **B**. Сеньор обновляет мнение по данным.

### Решение пользователя: **B — миграции владеют схемой**

Проверка фактом перед удалением кода: `App\Entity\*` и `App\Repository\*` —
**ноль внешних ссылок**, нет ассоциаций → удалять безопасно.

### План исполнения 1.0 (порядок A→B→C)
- **A. Снять авторитет с ORM:** удалить `src/Entity/*` + `src/Repository/*`; настроить
  `dbal.schema_filter` (или не пользоваться `diff`). *Приёмка:* `migrations:diff`
  даёт пустую миграцию, а не DROP-каскад.
- **B. Миграция-вперёд** (новая, SQL руками; старые не редактировать): `account.id`
  → UUID (`USING id::uuid`); `account.balance` → `numeric(18,2)` + `CHECK (>=0)`;
  `payment.amount` → numeric + CHECK; вернуть FK (UUID↔UUID); **не трогать**
  `UNIQUE (key)` (это 1.3); рабочий `down()`.
- **C. Код догоняет схему** (в том же заходе, иначе тесты лягут): получатель
  `CAST(...)` → `balance = balance + :amount`; тесты `'130'` → `'130.00'`.

*Критерий приёмки 1.0:* свежая БД → `numeric` баланс с `CHECK` + FK; `diff` пустой;
`phpunit`/`phpstan` зелёные.

### Senior-урок про прод
`ALTER COLUMN TYPE` берёт `ACCESS EXCLUSIVE` лок и переписывает таблицу → в проде
на горячей БД это даунтайм. Безопасный путь: expand-contract (новая колонка →
backfill → переключение → drop) или `pg_repack`. «Просто `ALTER`» в проде — роскошь.

## Лог решений

| Решение | Выбор | Почему |
|---|---|---|
| Уровень PHPStan | **Level 8** | baseline уже под него; строже; ловит numeric-string |
| Имя phpstan-конфига | `phpstan.dist.neon` | конвенция репо (`phpunit.dist.xml`) |
| `ext-http` | **удалить** | не используется, тащит боль в CI |
| Сервисы в CI | **только Postgres** | transfer-путь не трогает Redis/RabbitMQ |
| Источник правды по схеме (1.0) | **B: миграции** | финтех, CHECK вне ORM, write уже на DBAL |
| Судьба ORM-сущностей | **удалить** | ноль ссылок, мёртвый код = вектор регрессии |

## Принципы / уроки сессии (дистиллят)
1. **Проверяй по артефакту, а не по памяти/документу** — каждый раз спасало.
2. **Перед удалением кода — найди все ссылки** (`grep`), а не «вроде не используется».
3. **Baseline статанализа = бэклог рефакторинга**, привязан к уровню.
4. **Схема — самый долговечный контракт**; её гарантии (CHECK/FK/типы) — последняя
   линия обороны, держатся даже при багах в коде.
5. **Единый источник правды**: два хозяина одного артефакта = тихий конфликт.
6. **Декларативный инструмент защищает только выразимое; чего не понимает — сносит.**
7. **Схема и код связаны**: меняешь тип колонки — чини пишущий код в том же заходе.
8. **Fix-forward**, закоммиченные миграции не редактируются.
9. **Атомарные, заскоупленные коммиты**; trogаешь `require` → lock в том же изменении.
10. **Сеньор обновляет рекомендацию по новым фактам**, а не держится за прошлый вывод.
